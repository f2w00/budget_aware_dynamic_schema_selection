# Gold 标注会话操作说明

## 任务性质

这是一个文物信息的语义标注任务，不是编程任务。

请直接阅读我提供的文物记录，理解原文内容，并输出该记录的 Gold 字段结果。

不要编写 Python、Bash、正则表达式、映射规则或其他脚本。不要调用数据库、
外部工具或外部知识。不要修改输入文件或创建自动化处理流程。

你只需要完成三件事：

```text
阅读 raw_data
理解 18 个字段的含义
直接输出字段结果
```

## 输入记录

每条记录的格式如下：

```json
{
  "artifact_id": 1276,
  "raw_data": {
    "年代": "魏晋南北朝",
    "类型": "瓷器",
    "文物名称": "西晋青瓷罐",
    "详细描述": "年代：魏晋南北朝；尺寸：口径9.5，底径9.2，高14.9 厘米；类别：瓷器"
  }
}
```

`artifact_id` 只用于识别和匹配记录。不要根据它推断文物信息；输出时必须原样复制，
不能修改、转换或省略。
标注只依据同一条记录中的 `raw_data`。

## 标注原则

- 只使用 `raw_data` 中明确出现的信息。
- 不使用 `artifact_extract`、互联网、知识库或常识进行补全。
- 必须逐一考虑下面列出的全部 18 个字段。
- 有可靠原文依据时输出字段。
- 没有可靠原文依据时省略字段，不输出 `null`。
- 不确定的信息宁可省略，不要猜测。
- 允许对原文进行直接、低风险的中文归一化，但不能改变原文事实。
- 多个原文明确列出的值可以使用数组；没有明确多值时不要自行拆分。

## 字段定义

| 字段 | 含义和判断范围 |
|---|---|
| `name` | 文物名称。通常来自“文物名称”等明确名称字段；只填写原文给出的名称。 |
| `category` | 文物类别，如陶器、瓷器、青铜器、书画、玉器等。它描述文物属于哪一类，不是材质本身。 |
| `form_type` | 器型或形制，如鼎、瓶、罐、俑、镜等。只有原文明确给出，或文物名称直接包含清楚的器型时才填写。 |
| `usage` | 用途或功能，如礼器、明器、兵器、食器、生活用具等。不能仅根据器型或材质推断用途。 |
| `desc` | 基于原文的文物简介或综合描述。可以概括名称、年代、尺寸和原文中的其他事实，但不能添加历史背景或推测。 |
| `condition` | 保存状态，如完整、残缺、修复、残损等。只有原文明确描述保存状态时才填写。 |
| `dynasty` | 朝代、政权或较大的历史时代，如商、唐、宋、明、魏晋南北朝等。 |
| `period` | 比朝代更具体的历史时期、阶段或年号，如西周早期、盛唐、嘉靖、乾隆等。 |
| `acq_type` | 文物取得、收藏或流传方式，如考古发掘、传世、捐赠、征集、购买等。 |
| `region` | 来源地区或较大地理区域，如河南、陕西、江南地区等。只有原文明确给出地区时才填写。 |
| `site` | 具体出土、发现或来源地点，如殷墟、马王堆、某墓、某窑址等。具体地点优先放在此字段。 |
| `culture` | 文化归属，如中原文化、吴越文化等。不能仅根据年代、地区或器物类型推断。 |
| `material` | 主要制作材质，如陶、瓷、青铜、玉、木、纸等。`category` 是类别，`material` 是材质，两者不要混淆。 |
| `motif` | 主要纹饰、图案或装饰主题，如龙纹、兽面纹、莲花纹等。原文没有纹饰信息时省略。 |
| `craft` | 主要制作工艺，如范铸、拉坯、刻花、镶嵌、绘制等。不能仅凭材质或器型推断工艺。 |
| `craft_school` | 流派、窑口或制作体系，如越窑、汝窑等。只有原文明确提到时才填写。 |
| `related_event` | 与这件文物直接相关的历史事件。不能因为文物属于某朝代就填写该朝代的著名事件。 |
| `related_person` | 与这件文物直接相关的人物。不能根据时代、器物类型或外部知识推断人物。 |

## 容易混淆的字段

### `dynasty` 和 `period`

朝代、政权或较大的历史时代填写 `dynasty`；具体时期、阶段或年号填写 `period`。

例如：

```json
{
  "dynasty": "明",
  "period": "嘉靖"
}
```

如果原文只有“魏晋南北朝”，填写 `dynasty` 即可，不要强行生成 `period`。

### `category` 和 `material`

`category` 表示文物类别，`material` 表示制作材质。

例如，原文明确写有“瓷器”，可以标注：

```json
{
  "category": "瓷器",
  "material": "瓷"
}
```

但不能因为类别是青铜器，就进一步推断具体合金、制作方法或用途。

### `region` 和 `site`

省、地区或较大范围填写 `region`；具体遗址、墓葬、窑址、出土地或来源地点填写
`site`。只有原文明确出现地点时才填写。

### `form_type` 和 `usage`

`form_type` 是“它是什么器型”，`usage` 是“它用于什么”。名称中出现“罐”可以支持
`form_type` 为“罐”，但不能仅凭“罐”推断用途。

## 输出要求

只输出 JSON 对象，不输出解释、分析过程、Markdown 代码围栏或其他文字。

输出对象必须包含原样复制的 `artifact_id`，以及以下 18 个英文 Schema 键中的有值字段：

```text
name, category, form_type, usage, desc, condition, dynasty, period,
acq_type, region, site, culture, material, motif, craft, craft_school,
related_event, related_person
```

有可靠依据的字段直接输出，例如：

```json
{
  "artifact_id": 1276,
  "name": "西晋青瓷罐",
  "category": "瓷器",
  "form_type": "罐",
  "dynasty": "魏晋南北朝",
  "material": "瓷",
  "desc": "西晋青瓷罐，年代为魏晋南北朝。"
}
```

没有可靠依据的 Schema 字段直接省略。不要输出以下内容：

```text
schema_version
raw_data
reference_result
null
"null"
"未知"
"未详"
```

如果一次提供多条记录，每条输出必须带对应的 `artifact_id`，且每个输入 ID 有且仅有
一个输出。输出可以与输入顺序不同，补全脚本会按 `artifact_id` 匹配并按输入顺序写出。
不得遗漏、重复或伪造 ID。不要合并记录，也不要在 JSON 前后添加序号、说明或评论。

## 最终提醒

这是逐条阅读和判断任务。不要尝试设计自动抽取规则，也不要把本任务改写成脚本任务。
请阅读记录后直接给出 JSON 结果。
