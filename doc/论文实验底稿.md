# 第一部分：面向大规模文化遗产抽取的预算感知动态 Schema 选择

## 文档定位

本文档是论文第一部分的最终底稿，不是实验计划或待办清单。文中只把已经完成的
离线实验和真实 LLM 运行作为结果陈述；尚未完成的评分、图表和人工验证单独列在
“未完成项目与论文呈现边界”中，不将其写成已验证结论。

本部分聚焦一个问题：在大规模、信息密度不均的文化遗产记录抽取中，能否先根据
记录内容预测字段需求，再为每条记录生成较小的动态 Schema，从而减少 LLM 调用
中的 Schema 负载，同时保持可接受的字段级抽取质量。

本部分不讨论并行系统的吞吐扩展性。生产者-消费者调度、并发度、队列背压和多进程
或多节点执行属于论文第二部分；这里只保留动态 Schema 对输入规模和 Token 消耗
的影响，作为后续系统实验的输入。

---

## 1. 研究问题与核心结论

### 1.1 研究背景

项目面向约 55 万条文化遗产记录的结构化信息抽取。原始记录来自异构数据源，
其键名、结构、信息密度和描述长度均不一致。有些记录只包含名称、类型和年代，
另一些记录同时包含工艺、纹饰、来源、历史关系和长篇描述。若对所有记录都发送
完整 18 字段 Schema，会在信息不足的记录中引入大量不会产生有效输出的字段定义，
并增加输入 Token、输出 Token 和推理成本。

传统完整 Schema 流程为：

```text
原始记录 + 完整 Schema -> LLM -> 结构化结果
```

本文研究的动态流程为：

```text
原始记录 -> 字段可抽取性/长度预测 -> 预算约束字段选择
         -> 记录级动态 Schema -> LLM -> 结构化结果
```

### 1.2 研究问题

第一部分围绕以下问题组织：

- RQ1：少量 FullSchema 启动样本能否训练出有效的字段选择器？
- RQ2：字符和词级文本特征如何影响字段存在性与输出长度预测？
- RQ3：动态字段选择能否在真实 LLM 调用中减少 Token，并保持可接受的字段级质量？
- RQ4：硬预算、软成本惩罚和外部 SchemaRAG 方法之间的质量-Token 权衡有何差异？
- RQ5：当前监督信号和评估设置还缺少哪些证据，限制了结论的范围？

### 1.3 当前可成立的核心结论

在冻结的 `gold_main` 500 条记录、`kg-assist-pro`、`temperature=0` 和 stable Prompt
条件下，M1 n=100 的动态字段选择器已经完成三个独立 seed 的真实 LLM 实验。当前
结果支持以下受限结论：

1. 仅使用 100 条 FullSchema 启动样本训练的 M1 选择器，可以在真实 LLM 抽取中
   形成稳定的质量-Token 权衡，而不是只在离线回放中有效。
2. `budget-200` 是当前最适合作为主方案的配置：三 seed 平均 Presence Macro-F1
   为 0.7644、Micro-F1 为 0.7673、Exact Value Recall 为 0.6470，平均总 Token
   为 385.5，Gold 非空字段覆盖率为 0.8381。
3. 在与历史 FullSchema 共同成功的 476 条记录上，M1 `budget-200` 的 Presence
   Micro-F1 为 0.7660，FullSchema 为 0.7410；平均总 Token 分别为 385.9 和
   539.8，描述性上减少约 28.5%。由于两者来自不同运行批次，不能据此宣称严格
   配对优于 FullSchema。
4. `lambda=-0.003` 通过放松硬预算提高了字段覆盖率，但平均总 Token 增加到
   462.2；`budget-400` 的覆盖率进一步提高，却没有带来更高的 Presence 或
   Exact Value Recall。这说明选中更多字段不必然产生更好的端到端结果。
5. 这些结果证明的是字段存在性、部分精确值匹配和 Token 方面的改进潜力，尚不
   足以证明综合抽取质量、人工真实性、无幻觉率或真实货币成本全面改善。

## 2. 数据、监督信号与评估隔离

### 2.1 数据组织

原始记录和 FullSchema 结果通过 `artifact_id` 对齐：

```text
public.artifact_raw(
    artifact_id bigint primary key,
    raw_data jsonb not null
)

public.artifact_extract(
    artifact_id bigint primary key,
    acq_type, category, condition, craft, craft_school, culture,
    desc, dynasty, form_type, material, motif, name, period,
    region, related_event, related_person, site, usage
)
```

`artifact_extract` 是既有 FullSchema 抽取结果，属于 model-assisted silver reference，
不是独立人工 Gold，也不是动态 Schema 的结果。训练输入只来自 `artifact_raw.raw_data`，
不能从 `artifact_extract` 反向生成输入文本，以避免目标泄漏。

### 2.2 数据规模与划分

通过两表内连接得到 6,763 条记录，稳定序列化原始 JSON 得到 `record_text`。固定
划分如下：

| 划分 | 数量 | 用途 |
| --- | ---: | --- |
| Train | 5,410 | 训练池，所有训练规模均从此抽样 |
| Validation | 677 | 选择字段分类阈值 |
| Test | 676 | 离线最终评估 |
| `gold_main` | 500 | Test 中冻结的真实 LLM 评估子集 |

Train、Validation 和 Test 按 `record_id` 互斥；`gold_main` 完全属于 Test，且不与
Train 或 Validation 重叠。训练量消融使用 50、100、250、500、1000、2500 和 5410
条七个规模，每个规模使用 seed 42--46。固定 seed 下，小规模样本是由多标签缺口
贪心顺序构造的大规模训练前缀，不应解释为完全独立的均匀随机样本。

### 2.3 监督标签

对 18 个目标字段构造两类标签：

- `present`：FullSchema 结果为非空值时记为 1，否则记为 0；
- `field_output_tokens`：使用 `cl100k_base` 对 FullSchema 字段值计数，空值为 0。

这两个标签描述的是既有 FullSchema 输出行为，不保证字段值真实，也不保证原文中
存在明确证据。因此，训练结果应称为 FullSchema-derived silver supervision。

## 3. 方法：小样本字段预测与动态 Schema 生成

### 3.1 M1 选择器

M1 使用字符级和词级 TF-IDF 特征拼接：

```text
record_text
   -> char TF-IDF (2-5 gram) ----┐
                                 -> concatenated features
   -> word TF-IDF (1-2 gram) ----┘
```

Presence 分支为每个字段训练一个 `LogisticRegression`，使用 balanced class weight；
Length 分支在字段非空样本上训练 `Ridge(alpha=10)`，回归目标为
`log1p(field_output_tokens)`。验证集用于选择字段独立阈值，阈值向 0.5 收缩 25%，
并限制在 0.10--0.90。正样本不足 10 条的字段使用训练集非空 Token 中位数作为长度
预测兜底。

`name`、`category` 和 `desc` 在训练数据中正样本率为 100%，其表现应理解为常量或
必选字段先验，而不是分类器已经学习了有效区分能力。`craft`、`site`、`acq_type`、
`craft_school` 和 `related_event` 等稀有字段则受正样本数量限制，属于当前方法的
主要长尾风险。

### 3.2 字段效用与成本

每条记录、每个字段的预期效用定义为：

```text
utility(r, f) = present_score(r, f) * field_value_weight(f)
```

字段价值权重来自任务先验配置。`name` 和 `category` 默认作为必选字段，其余字段
使用任务相关权重；这些权重不是从数据中自动学习的客观价值。

字段选择阶段的估计成本为：

```text
cost(r, f) = schema_definition_tokens(f)
              + predicted_output_tokens(r, f)
```

对候选字段执行 0-1 背包选择：

```text
maximize   sum utility(r, f)
subject to sum cost(r, f) <= B
```

需要区分字段选择预算和端到端 API Token：`budget-200` 与 `budget-400` 约束的是
`estimated_field_cost`，不是总输入输出 Token 上限。真实总消耗还包括原文输入、固定
Prompt、实际输出和重试。

### 3.3 三种动态策略

本轮真实 LLM 主分析保留三种 M1 策略：

| 策略 | 选择规则 | 解释 |
| --- | --- | --- |
| `budget-200` | 硬预算 200 的 0-1 背包 | 主方案，强调 Token 压缩 |
| `budget-400` | 硬预算 400 的 0-1 背包 | 高覆盖率对照 |
| `lambda=-0.003` | 效用减预测成本的软惩罚 | 高覆盖、无硬预算对照 |

完整 18 字段 FullSchema 是主要内部基线。Prompt-only 方法用于检查“仅靠 Prompt
让模型忽略无信息字段”是否可以替代 Schema 裁剪；SchemaRAG 是按公开论文描述进行
的外部独立重实现，不是官方代码复现。

## 4. 离线实验结果

### 4.1 训练样本量消融

原始字符 TF-IDF 与 M1 在固定 Test 上的五 seed 均值如下：

| 训练量 | 原始 Macro-F1 | M1 Macro-F1 | 原始 Micro-F1 | M1 Micro-F1 | 原始 Length MAE | M1 Length MAE |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 0.5156 | 0.4990 | 0.8909 | 0.9215 | 4.9682 | 4.9307 |
| 100 | 0.5187 | 0.5088 | 0.9126 | 0.9343 | 4.8046 | 4.7615 |
| 250 | 0.5522 | 0.5455 | 0.9296 | 0.9445 | 3.7907 | 3.7199 |
| 500 | 0.5940 | 0.5824 | 0.9362 | 0.9492 | 3.5017 | 3.4228 |
| 1000 | 0.6245 | 0.6075 | 0.9459 | 0.9517 | 3.3123 | 3.2363 |
| 2500 | 0.6916 | 0.6450 | 0.9590 | 0.9561 | 3.0084 | 2.9525 |
| 5410 | 0.7139 | 0.6962 | 0.9646 | 0.9612 | 2.9678 | 2.9100 |

M1 在小到中等训练规模上提高 Micro-F1 和长度预测，但 Macro-F1 在所有规模均低于
原始字符模型，说明拼接词级特征的收益主要集中在高频字段，未解决长尾字段的均衡
识别问题。M1 n=100 的五 seed 均值为 Macro-F1 0.5088、Micro-F1 0.9343、Length
MAE 4.7615，因此选择 n=100 作为真实 LLM 实验的“小样本启动”方案，不将其表述为
最优通用离线模型。

### 4.2 M2 负结果

M2 分别训练字符级和词级分类器，再在验证集上融合概率。五 seed 均值为 Macro-F1
0.5083、Micro-F1 0.9341、Length MAE 4.7615，略低于 M1；Budget-400 覆盖率也略低。
因此没有采用 M2。该负结果说明，在当前数据量和特征设置下，概率后融合没有提供
可观测的额外收益。

### 4.3 离线预算回放

在 6,763 条记录上，以 FullSchema 非空字段集合作为参照，字段选择器的离线回放为：

| 预算 | 平均估计字段成本 | 平均选中字段数 | FullSchema 非空字段覆盖率 |
---:|---:|---:|---:|
| 100 | 90.52 | 2.75 | 26.06% |
| 200 | 192.67 | 4.81 | 53.46% |
| 400 | 385.04 | 8.23 | 94.95% |

预算提高会增加选中字段和离线覆盖率，但离线覆盖率不等于重新调用 LLM 后的真实
字段值质量，也不等于 API 成本。真实 LLM 结果是本部分的主要证据。

## 5. 真实 LLM 实验

### 5.1 固定条件

所有新一轮 M1 实验均使用冻结的 `gold_main` 500 条记录、三个训练 seed（42、43、44）、
`kg-assist-pro`、`temperature=0`、关闭 Qwen3 thinking、stable Prompt、并发 20、
队列容量 40 和最多 2 次重试。每种方法在三个 seed 下各完成 500 条记录，正式结果
均为 500/500 成功，未出现最终失败或协议异常。

稳定版 Prompt 只允许依据 raw 中明确出现或可直接归纳的信息；普通字段主要提供英文
键名，少数重点字段提供简短中文说明，避免模型复制过长的 Schema 描述。正式实验使用
的 Prompt hash 为 `3ce8b14daaf4c285`。

### 5.2 M1 三策略主结果

以下为三个 seed 的平均值，Token 是真实运行记录中的输入与输出累计值：

| 方法 | Presence Macro-F1 | Presence Micro-F1 | Exact Value Recall | Gold 字段覆盖 | 输入 Token | 输出 Token | 总 Token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| M1 + `budget-200` | 0.7644 | 0.7673 | 0.6470 | 0.8381 | 321.1 | 64.4 | 385.5 |
| M1 + `lambda=-0.003` | 0.7460 | 0.7544 | 0.6497 | 0.9878 | 342.0 | 120.1 | 462.2 |
| M1 + `budget-400` | 0.7246 | 0.7329 | 0.6323 | 0.9906 | 360.7 | 132.4 | 493.2 |

`budget-200` 在三 seed 间保持相近的结果，是当前论文主方案。它不是覆盖率最高的
策略，但在较低 Token 消耗下取得了最高的 Presence Macro-F1、Micro-F1，并且 Exact
Value Recall 与另外两种策略处于相近水平。`lambda` 和 `budget-400` 提供了重要的
反例：更高字段覆盖并不会自动转化为更高的端到端质量。

### 5.3 与内部 FullSchema 的描述性对照

历史 FullSchema 运行与新 M1 运行并非同一调用批次，因此只使用共同成功的 476 条
`artifact_id` 做描述性对照：

| 方法 | Presence Macro-F1 | Presence Micro-F1 | Exact Value Recall | Gold 字段覆盖 | 平均总 Token |
| --- | ---: | ---: | ---: | ---: | ---: |
| FullSchema | 0.7623 | 0.7410 | 0.6528 | 1.0000 | 539.8 |
| M1 + `budget-200` | 0.7639 | 0.7660 | 0.6439 | 0.8357 | 385.9 |
| M1 + `lambda=-0.003` | 0.7444 | 0.7531 | 0.6467 | 0.9872 | 463.4 |
| M1 + `budget-400` | 0.7242 | 0.7329 | 0.6295 | 0.9901 | 493.9 |

相对于 FullSchema，M1 `budget-200` 的平均总 Token 从 539.8 降至 385.9，描述性
下降约 28.5%；Presence Micro-F1 数值更高，但 Exact Value Recall 略低。由于
FullSchema 与 M1 的调用时间、运行批次和结果形成过程不同，这一表不能支持严格的
显著性或因果优越性结论。论文中应将其称为 aligned descriptive comparison。

### 5.4 与 SchemaRAG 的外部方法对照

SchemaRAG k=10 和 k=15 是依据论文描述进行的独立重实现，官方代码未公开。完整
`gold_main` 500 条上的结果为：

| 方法 | Presence Macro-F1 | Presence Micro-F1 | Exact Value Recall | Gold 字段覆盖 | 输入 Token | 总 Token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| SchemaRAG k=10 | 0.7069 | 0.7022 | 0.4796 | 0.8078 | 327.5 | 432.9 |
| SchemaRAG k=15 | 0.7324 | 0.7224 | 0.5524 | 0.9888 | 368.6 | 503.6 |
| M1 + `budget-200` | 0.7644 | 0.7673 | 0.6470 | 0.8381 | 321.1 | 385.5 |

该表支持一个谨慎的描述性观察：在当前实现、Prompt、模型和调用批次下，M1
`budget-200` 同时获得较高的字段级指标和较低的 Token。但由于 SchemaRAG 为外部
重实现而非官方复现，不能把该结果写成对原论文方法的严格复现性否定或普遍优越性。

## 6. 结果解释与局限

### 6.1 方法贡献的准确表述

本部分的贡献应表述为：

- 将 FullSchema 的银标字段信息转化为记录级字段需求预测问题；
- 用少量启动样本训练字段存在性和输出长度预测器；
- 将字段价值先验、预测输出长度和预算约束整合到动态 Schema 选择中；
- 在真实 LLM 调用中验证了小样本动态选择的质量-Token 权衡，而不只报告离线覆盖率；
- 发现提高字段覆盖率并不保证提高最终抽取质量，为预算选择提供了可复现的反例。

不应表述为“动态 Schema 在所有字段上提高准确率”“已经证明综合质量全面优于
FullSchema”或“已经证明 API 费用下降”。当前证据只支持 Presence、Exact Value
Recall 和 Token 维度的受限结论。

### 6.2 主要限制

1. **银标偏差**：训练标签和 `gold_main` 参考结果来自既有 FullSchema/模型辅助流程，
   不是独立人工标注，可能把源模型偏差传递给字段选择器和评估指标。
2. **长尾字段不足**：稀有字段的正样本有限，M1 的 Macro-F1 低于原始字符模型；
   当前方法对长尾字段的恢复能力仍不稳定。
3. **字段覆盖与质量不等价**：动态 Schema 未选中的字段会被视为预期缺失，较低覆盖率
   可能同时带来 Token 节省和信息损失，必须与字段值质量一起解释。
4. **评估尚不完整**：Presence 只判断字段是否非空，Exact Value Recall 只反映严格
   值匹配，二者不能充分评价描述字段、同义表达、部分正确值或事实真实性。
5. **方法对照存在批次差异**：新 M1 与历史 FullSchema 的 476 条结果并非在完全相同
   的一次 API 调用批次中产生，因此 aligned 结果是描述性而非严格统计比较。
6. **外部基线是重实现**：SchemaRAG k=10/k=15 未使用官方实现，Embedding 模型、
   参数和提示适配可能影响结果。
7. **成本尚未货币化**：当前 API 单价环境变量未配置，报告中的 `actual_cost` 为
   空或 0 只表示未换算价格，不表示真实调用没有成本。Token 统计包含重试消耗。
8. **固定并发不是方法收益**：本轮统一并发 20、队列 40 只是运行条件，不能把本轮
   墙钟时间差异解释为动态 Schema 的吞吐优势。

## 7. 未完成项目与论文呈现边界

下列项目目前缺失，论文正式投稿前应补充；在补充前，正文应明确写成限制或未来工作：

- 非 `desc` 字段的 LLM Value Judge，包括字段级评分、评分理由、模型版本和 Prompt hash；
- `desc` 字段基于固定 Embedding 模型的语义相似度评分；
- 预先定义的综合 Quality：`0.5 * Presence-F1 + 0.3 * LLM-Value-Score +
  0.2 * Desc-Embedding-Score`；
- 同一 `artifact_id` 上的综合质量-Token 配对统计、置信区间和显著性检验；
- 人工 Gold 或人工证据验证集，用于评估字段值真实性和无原文支持输出比例；
- 预测字段成本与实际 Token、费用之间的误差分析；
- 字段价值权重敏感性分析；
- 论文图表：方法流程图、训练量学习曲线、质量-Token 曲线、字段覆盖率图和长尾字段
  误差图。

因此，当前版本可以作为论文第一部分的完整方法与阶段性实证底稿，但正式论文中
“最终质量最优”“真实费用最低”“无幻觉率下降”等措辞必须等上述证据补齐后才能使用。

## 8. 可复现实验产物

### 8.1 数据与模型

```text
training_dataset.jsonl
```

## 9. 第一部分在全文中的位置

第一部分建立“记录感知字段选择能够减少 LLM Schema 负载”的方法和质量-Token 证据。
第二部分将在相同方法和结果记录基础上，研究有界生产者-消费者流水线、并发扩展、
队列背压以及多进程或多节点任务分片。两部分的连接是：第一部分产生每条记录的动态
Schema 与 Token 需求，第二部分检验这种负载缩减能否在高性能预处理系统中转化为更高
吞吐和更短 makespan。第一部分本身不提前声称已经完成这些系统级结论。

## 10. 版本结论

截至当前实验版本，第一部分的主方案确定为：

```text
M1 n=100 + stable Prompt + budget-200
```

论文主叙事应从“设计了一个尚待验证的预算选择器”改为“用少量 FullSchema 银标启动
训练动态字段选择器，并在真实 LLM 上验证其质量-Token 权衡”。主结果使用完整
`gold_main` 500 条和三个 seed；历史 FullSchema 的 476 条共同成功结果用于 aligned
描述性对照；SchemaRAG 用作独立外部重实现对照。综合质量、人工真实性、货币成本、
图表和证据验证仍明确标为待补证据，不影响当前方法主线，但限制最终结论强度。
