# 外部批次 n=100 字段选择验证实验记录

## 目的

验证字段选择器在既有实验数据之外的 `artifact_raw` 新 ID 批次中，能否仅用少量
同批次 silver labels 学习字段需求，并在严格保留测试集上削减待注入 Prompt 的字段规模。

本实验不运行新的 `budget-200/400` LLM 流水线；因此不报告或推断新批次的端到端吞吐、
延迟、真实 API Token 或抽取质量。

## 冻结输入

- 候选范围：`artifact_id > 400000001`，数据库候选记录 `481,600` 条。
- 与既有 `training_dataset.jsonl`、`data/gold/gold_main_ids.json` 和
  `data/performance/performance_ids_2000.json` 的合并 `6,763` 个唯一 ID 零重叠。
- 从原始 JSON 字节长度的五个 NTILE 层中，以固定 seed `20260916` 各抽取 `100` 条，
  共 `500` 条；输入快照为
  `data/external_batch_400000001/snapshot.jsonl`，SHA256 为
  `174d1d99c0b407274e780cc31144ff9d22dc16941aebfa06591221192df0f7a8`。
- 详细分层和零重叠审计见
  `data/external_batch_400000001/manifest.json`。

## Silver 标签

- 对冻结的 500 条记录仅运行一次 `full`，固定 `kg-assist-pro`、temperature `0`、
  `1_stable.prompt`、`simple2.json`、并发 `20`、队列 `40`、最多重试 `2`。
- dry-run 500 条和独立 smoke 2 条先后均通过；正式 500/500 成功、0 重试。
- 正式输出：`experiments/external_batch_400000001_full_silver/formal/full.jsonl`。
- 正式调用总 input/output/total Token 为 `212,010 / 62,046 / 274,056`，每条平均
  `424.02 / 124.09 / 548.11`；这些数据仅用于构造 silver labels，不与后续离线
  Prompt 指标混同。

## 切分与模型

- 从完整 500 条 full silver 输出构造 Presence 标签后，以两阶段多标签迭代分层固定为
  `100 train / 50 validation / 350 held-out test`，split seed 为 `20260916`。
- 训练仅使用 100 条；阈值仅在 50 条 validation 选择；最终指标仅对 350 条 held-out
  test 计算。
- M1：字符 2--5 gram 与词级 1--2 gram TF-IDF 拼接，逐字段 balanced LogisticRegression
  (`liblinear`)；验证集 F1 最优阈值向 0.5 收缩 25%；长度使用 Ridge/中位数常量。
- 在固定划分下该拟合是确定性的，因此报告单一冻结 hold-out 验证，不将相同训练的伪重复
  作为独立 seed 方差。

## Held-out 结果

字段预测指标：

| 指标 | 结果 |
| --- | ---: |
| Presence Macro-F1 | 0.5575 |
| Presence Micro-F1 | 0.6519 |
| Length MAE | 2.8588 |

离线预算 Pareto（同一 350 条 held-out，无 LLM 调用）：

| 预算 | 平均 Gold 非空字段覆盖 | 平均选择字段数 | 平均估计字段成本 | 成本不超过预算比例 | Prompt 平均本地 Token | Token 减少比例 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Budget-200 | 0.6957 | 5.6143 | 194.2771 | 1.0000 | 382.3714 | 20.2144% |
| Budget-400 | 0.8619 | 9.7057 | 396.0314 | 1.0000 | 428.0971 | 10.6733% |

Full Prompt（18 字段）平均本地 Token 为 479.2486，作为两个预算的共同参照。预算放宽到 400
会把覆盖从 0.6957 提升到 0.8619，但 Prompt Token 减少比例从 20.21% 降到 10.67%，覆盖与
输入规模之间存在明显权衡。

Prompt Token 使用同一 `1_stable.prompt` 和 `llm_prompt.build_prompt()` 构造，再以
`cl100k_base` 本地编码；它是确定性的输入规模代理，不能替代远程服务实际计费 Token 或
端到端时间。

## 结论边界

结果支持：在与既有实验 ID 零重叠的新批次中，以同批次 100 条 full silver labels 训练的
M1 能在 350 条严格保留记录上预测字段 Presence，并提供可调的离线预算权衡：Budget-200
将 Prompt 输入规模降低约 20.21% 但 Gold 覆盖为 0.6957，Budget-400 覆盖提升到 0.8619
但 Token 减少比例降到 10.67%。

结果不支持：跨机构/跨数据源的人工事实泛化、端到端吞吐或延迟改善、真实 API Token 节省，
也不能把 model-assisted silver labels 当作人工 Gold。
