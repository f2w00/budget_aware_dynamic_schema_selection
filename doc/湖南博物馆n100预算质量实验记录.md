# 湖南博物馆 n=100 预算质量实验记录

## 目的

验证动态 Schema 方法能否在一个独立、连续的湖南博物馆记录批次中，仅使用同批次
100 条 full silver labels 训练 M1，并在严格保留的 350 条记录上保持抽取质量、降低实际
LLM Token 用量。

本实验不将并发执行时间、吞吐、队列等待或尾延迟作为结果或结论。`c=20,q=40` 仅用于
提高正式质量实验的执行效率。

> 口径说明：下表质量参考为被测模型 full 输出的 held-out 子集（同源循环口径）。为消除循环偏差，
> 另见 `doc/湖南博物馆外部参考质量对照实验记录.md`：以独立证据参考（`agent-evidence-reference-v2`）
> 重评 `full`/`budget-200`/`budget-400`，结论仅用于方法间横向对比；本文 Token 结论不受影响。

## 冻结输入与银标

- 固定 ID 区间：`artifact_id=300000001..300000500`，连续 500 条，不做随机抽样。
- 输入快照：`data/hunan_museum_300000001_300000500/snapshot.jsonl`，SHA256 为
  `655584615d81e2293883eef636eb8339196453d0f9e97e2b9aca323483c65f36`。
- ID 列表 SHA256：`b001abb954ee49d95555953ed5f19402c0a6b825e81fc190c1e709e22e1bdc33`。
- 与既有训练集、`gold_main`、2,000 条性能负载及前一外部 batch 的 ID 重叠均为 0。
- 对 500 条记录运行一次 full stable Prompt，输出
  `experiments/hunan_museum_300000001_300000500_full_silver/formal/full.jsonl`；
  500/500 成功、0 重试、每条完整 18 字段。
- silver 构造使用 `kg-assist-pro`、temperature `0`、thinking 关闭、`1_stable.prompt`、
  `simple2.json`、max retries `2`。Prompt hash 为 `3ce8b14daaf4c285`，Schema hash 为
  `8c9969277e238283`。

## 切分与模型

- 基于 full silver Presence 标签，以两阶段多标签迭代分层固定为
  `100 train / 50 validation / 350 held-out test`，split seed `20260917`。
- 训练只使用 100 条，阈值只使用 50 条 validation，所有 budget 质量指标仅在 350 条
  held-out 上计算。
- M1 使用字符 2--5 gram 与词级 1--2 gram TF-IDF 拼接、逐字段 balanced
  LogisticRegression（`liblinear`）、validation F1 最优阈值向 0.5 收缩 25%，以及
  Ridge/中位数长度估计；模型为
  `models/hunan_museum_300000001_300000500_n100_m1/seed_42/model.joblib`。
- 原始 M1 Presence 指标：Macro-F1 `0.9279`，Micro-F1 `0.9295`，Length MAE `1.2923`。

## 正式预算质量实验

- 方法：`budget-200`、`budget-400`；每种方法运行相同的 350 条 held-out 记录。
- 两种方法均使用同一快照、M1 模型、stable Prompt、Schema、服务模型和 temperature；
  `c=20,q=40,max-retries=2`。
- dry-run 各 350 条与 smoke 各 2 条均通过，正式运行两种方法各 350/350 success、0 error、
  0 retry、0 缺失/额外字段。
- 评估参考为由同一批 500 条 full 输出中抽取的 held-out 350 条 silver reference：
  `data/hunan_museum_300000001_300000500/heldout_full_silver_reference.jsonl`。

| 指标 | Budget-200 | Budget-400 |
| --- | ---: | ---: |
| 选择字段数 | 9 | 16 |
| 平均估计字段成本 | 195.9571 | 394.7200 |
| Presence Macro-F1 | 0.6709 | 0.8786 |
| Presence Micro-Precision | 0.9268 | 0.9526 |
| Presence Micro-Recall | 0.5258 | 0.8419 |
| Presence Micro-F1 | 0.6709 | 0.8938 |
| 平均选中 Gold 覆盖 | 0.5872 | 0.9098 |
| Exact Value Recall | 0.5082 | 0.7484 |
| 平均 input Token | 344.4857 | 390.3943 |
| 平均 output Token | 69.9171 | 121.6057 |
| 平均 total Token | 414.4029 | 512.0000 |
| 相对 full 平均 total Token 减少 | 22.60% | 4.38% |

同一 held-out 的 full silver 参照平均 total Token 为 `535.4371`（input `400.3943`，
output `135.0429`）。Budget-200 总 Token 为 `145,041`，Budget-400 为 `179,200`，full
参照为 `187,403`。

## 解释与边界

- Budget-200 保留约 22.60% 的实际 total Token 节省，但受 9 字段硬预算限制，Recall 和
  Exact Value Recall 明显低于 Budget-400。
- Budget-400 选择 16 个字段，Micro-F1 `0.8938`、Exact Value Recall `0.7484`，质量保持
  更好，但实际 total Token 仅比 full 少约 4.38%。
- full 输出在本实验中是 silver reference 的来源，不能再用 full 对自身计算 F1；表中结果只
  表示两个预算方法相对同批 held-out full silver 的一致性。
- 该参考不是人工 Gold，不能据此声称人工事实正确性或跨机构泛化；同样，未将并发执行时间
  用作性能结论。
