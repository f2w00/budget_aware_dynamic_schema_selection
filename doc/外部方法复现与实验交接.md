# 外部方法复现与实验交接

## 1. 任务目标

本项目研究面向文物原始 JSON 的 LLM 信息抽取。在每条记录上，方法先选择需要进入
Prompt 的目标字段 Schema，再由同一个 LLM 按选中的 Schema 输出结构化结果。

核心问题是：在尽量保持抽取质量的前提下，记录感知的 Adaptive Schema 能否减少端到端
LLM Token 消耗，并优于只用完整 Schema 或只修改 Prompt 的做法。

本任务由接手 Agent 完成已经指定的外部方法的核验、实现、适配和同条件实验。外部方法
不是由接手 Agent 自行挑选或替换；若方法名称、论文或代码链接未在任务消息中提供，应先
向任务发起人索取，不能自行以另一篇论文替代。

## 2. 当前论文方法与实验状态

本文内部方法的共同框架是：

```text
raw_data
  -> 字段选择策略
  -> selected_fields
  -> 由 selected_fields 构造 Prompt 和目标 JSON Schema
  -> kg-assist-pro 抽取
  -> 统一解析、重试、Token 统计和离线评估
```

当前正式主分析只保留以下 6 种方法：

| 方法 | 定位 |
| --- | --- |
| `full` | 完整 18 字段 Schema 的基础基线 |
| `prompt-null` | 完整 Schema，仅要求无可靠信息时输出 `null` |
| `prompt-omit` | 完整 Schema，允许无可靠信息字段省略输出 |
| `budget-200` | 选中字段的估计字段成本不超过 200 的 Adaptive Schema |
| `budget-400` | 选中字段的估计字段成本不超过 400 的 Adaptive Schema |
| `lambda-0.003` | 按字段效用减预测成本进行无硬预算选择的 Adaptive Schema |

`fixed-5` 和 `fixed-10` 已执行并保留在原始结果中，但固定集合由数据中较稠密的字段
构成，字段存在性指标有先验偏置。它们只能作为补充诊断，不能参与主比较表、主排序或
论文核心结论。

## 3. 已冻结的正式实验条件

外部方法必须使用以下相同条件；除字段选择策略外，不得改变任何一项。

| 项目 | 冻结配置 |
| --- | --- |
| 原始数据 | PostgreSQL `public.artifact_raw.raw_data` |
| 样本 | `data/gold/gold_main_ids.json` 中冻结的 500 个 `artifact_id` |
| Reference | `data/gold/agent_tasks/gold_main.jsonl`，18 字段 model-assisted silver reference |
| 输出 Schema | `simple2.json` 定义的 18 个字段 |
| LLM | `kg-assist-pro` |
| Temperature | `0.0` |
| 思考模式 | `enable_thinking=false`，由 `llm_runner.py` 固定 |
| Prompt | `1_stable.prompt`，外部方法使用基础 Prompt |
| 并发与队列 | `max_concurrency=20`、`queue_size=40` |
| 重试 | 首次请求加最多 2 次重试 |
| 解析与统计 | 复用 `llm_runner.py` 的 JSON 校验、重试、Token 和失败记录逻辑 |

已有 v3 Pro 内部结果：

```text
experiments/gold_main_v3_stable_pro_results.jsonl
reports/gold_main_v3_stable_pro_all_methods_paired_metrics.json
doc/正式实验记录.md
```

这些文件不允许覆盖。早期 v1/v2 文件为历史记录，不能与 v3 Pro 主结果混合。

## 4. 成本口径

必须区分字段选择预算与实际 API 消耗：

```text
estimated_field_cost
  = 选中字段名 Token + 字段定义 Token + 预测字段输出 Token

total_tokens
  = API 实际 input_tokens + API 实际 output_tokens
```

因此，`budget-200` 的 200 是选中字段的估计成本上限，不是完整请求的总 Token 上限。
完整请求还包含稳定 Prompt、原始 JSON 和实际输出。外部方法必须同时保存并报告
`estimated_field_cost` 和实际 `input_tokens`、`output_tokens`、`total_tokens`，不得只用
其中一种口径声称成本更低。

## 5. 外部方法复现要求

### 5.1 复现前核验

在编码前，接手 Agent 必须记录下列信息并写入新的复现说明：

1. 指定论文的完整题目、作者、发表版本、年份、DOI/arXiv/官方网页。
2. 指定算法的准确名称，以及论文中与“字段选择、Schema 裁剪或预算约束抽取”直接相关
   的步骤。
3. 是否存在作者公开代码；如有，记录仓库 URL、commit/tag、许可证和运行环境。
4. 外部方法的输入、字段选择规则、成本或预算定义、输出协议及默认超参数。
5. 当前项目与原论文在任务、数据、字段数、LLM 或成本定义上的不可避免差异。

优先复用官方实现。若无法直接运行或无法直接支持 18 字段 Schema，可以做基于论文描述的
重实现，但必须在文档、代码注释和实验报告中明确写为“基于论文描述的重实现”，不得称为
官方复现。

### 5.2 公平适配边界

外部方法只能替换以下步骤：

```text
raw_data -> selected_fields
```

不得改变：

- `raw_data` 的内容或预处理方式；
- 18 字段名称、字段定义、输出 JSON 类型和字段白名单；
- `kg-assist-pro`、temperature、稳定 Prompt、关闭思考、超时和重试；
- Gold/reference、冻结 ID 列表和评估指标；
- API 调用、结果规范化、Token 统计和失败记录规则。

如果外部论文本身并非字段选择方法，或无法被限制为只影响 `selected_fields`，必须先说明
不可公平适配的原因并向任务发起人确认，不能悄悄改动其他实验变量。

## 6. 建议实现方式

### 6.1 代码边界

复用当前 Runner，避免复制或另写一套 LLM 请求管线：

```text
llm_runner.py
  resolve_fields(...)
  -> external selector
  -> selected_fields
  -> build_prompt(...)
  -> run_request(...)
```

建议新增独立模块，例如：

```text
external_selector_<method_slug>.py
```

模块应暴露与现有选择器等价的接口，返回至少包含：

```python
{
    "selected_fields": [...],
    "estimated_cost": ...,
    "method_metadata": {...},
}
```

如外部算法不使用当前的预测字段长度或效用模型，仍须生成可审计的
`estimated_cost`，并将其成本定义、计算依据和与本文口径的差异写入元数据。

不要修改 `budget_selector.py` 或 `unbudgeted_selector.py` 的现有语义；外部方法必须使用
独立方法名与独立实现，避免污染内部实验结果。

### 6.2 方法命名与结果文件

使用稳定、可读的 method slug，例如：

```text
external-<method-slug>
```

正式结果必须写入新文件，示例：

```text
experiments/external_<method_slug>_gold_main_v3_pro_results.jsonl
reports/external_<method_slug>_gold_main_v3_pro_paired_metrics.json
doc/external_<method_slug>_reproduction.md
```

结果每行必须保留 `artifact_id`、`method`、`selected_fields`、`target_structure`、
`raw_data`、`estimated_field_cost`、`full_estimated_cost`、`prompt_hash`、`schema_hash`、
`model_name`、`result`、`raw_response`、输入输出 Token、重试信息、状态和错误信息。

不覆盖 `experiments/gold_main_v3_stable_pro_results.jsonl`，也不向其中追加外部方法结果。

## 7. 实验步骤

### 7.1 实现与单元验证

1. 阅读指定论文与官方实现，完成第 5.1 节的复现说明。
2. 实现外部 selector，并给出小型可重复输入的字段选择测试。
3. 确认每个 `selected_fields` 都是 `simple2.json` 中的字段，字段顺序稳定且无重复。
4. 确认算法的预算、阈值或超参数只由论文、训练集或 validation 冻结，不能依据 500 条
   Gold 主集结果回调。
5. 为外部方法增加 Runner 接入，不影响现有内部方法。

### 7.2 冒烟运行

先使用冻结 ID 列表前 10 条运行一次。冒烟仅验证管线，不得据此做质量结论。必须检查：

- 10 条任务均被写入成功或明确失败记录；
- 输出仅含选中字段，不出现 Schema 外键；
- `selected_fields` 确实来自外部算法而非回退到内部方法；
- `estimated_field_cost`、实际 Token、重试次数和失败原因均存在；
- 同一命令重跑会跳过已经成功的相同任务，而不会重复请求；
- 结果可被 `evaluate_llm_experiments.py` 读取。

### 7.3 500 条正式运行

冒烟通过后，使用完整冻结 ID 列表运行 500 条：

```text
LLM_MODEL=kg-assist-pro
LLM_TEMPERATURE=0.0
--ids-file data/gold/gold_main_ids.json
--limit 500
--max-concurrency 20
--queue-size 40
--max-retries 2
```

具体 method 参数、selector 参数和结果路径由外部方法实现决定，但必须写入复现说明。
运行完成后，统计提交数、唯一 `artifact_id` 数、最终成功数、最终失败数、重试任务数和
总重试次数；任何失败都保留在 JSONL 中，不删除或伪造成功。

## 8. 评估与主比较

外部方法必须先与以下 6 个主方法取共同成功的 `artifact_id`，再做配对比较：

```text
full
prompt-null
prompt-omit
budget-200
budget-400
lambda-0.003
external-<method-slug>
```

使用 `evaluate_llm_experiments.py` 输出并报告：

- Presence Macro-F1 和 Micro-F1；
- Reference-present Recall；
- Reference-absent FPR；
- Exact Value Recall，仅作为辅助诊断；
- 平均输入、输出和总 Token；
- 平均预计字段成本、字段覆盖率、延迟、重试和最终失败率；
- 相同 `artifact_id` 上相对于 6 个主方法的质量-Token 配对差异。

后续完整质量评估尚未实施。外部方法必须进入同一套后续评估，不能只和 Presence 指标比较：

```text
Quality = 0.5 x Presence-F1
        + 0.3 x LLM-Value-Score
        + 0.2 x Desc-Embedding-Score
```

其中非 `desc` 字段由 LLM Value Judge 依据 `raw_data`、字段定义、reference 和 prediction
进行字段级评分；`desc` 仅通过预先固定的 embedding 模型计算余弦相似度。两个评分模块
当前尚未实现，外部方法的最终论文结论必须等待其同条件结果。

## 9. 验收条件

接手 Agent 的交付必须包含：

1. 外部论文与实现来源的可核验复现说明。
2. 外部 selector 代码及最小测试。
3. 冒烟 JSONL、500 条正式 JSONL、评估 JSON 报告和运行命令。
4. 方法参数、代码版本、Prompt/schema hash、模型、温度、并发、重试和成本口径。
5. 与 6 种主方法的共同成功样本规模和配对指标表。
6. 失败记录、重试统计、已知不公平处与实验限制。
7. 对 `doc/正式实验记录.md` 的追加记录，只描述实际完成内容，不覆盖或改写已有结果。

## 10. 禁止事项与结论边界

- 不自行更换任务方指定的外部方法。
- 不使用外部论文在其他数据集、模型或指标上的数字代替本项目实验。
- 不根据 500 条 Gold 主集的结果调整外部方法阈值、预算或字段选择规则。
- 不将 `fixed-5`、`fixed-10` 纳入主比较或主排序。
- 不把 `budget-200`、`budget-400` 称为端到端 API 总 Token 上限。
- 不把当前 model-assisted silver reference 表述为独立人工 Gold。
- 外部方法没有完成同条件复现、共同成功配对和完整质量评估前，不得宣称本文方法优于该
  外部方法。
