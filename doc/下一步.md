# 当前下一步

## 第二部分状态

第二部分动态 Schema 流水线的核心性能实验已经完成。正式结果覆盖：

- 2,000 条冻结性能工作负载；
- `full`、`budget-200` 和 SchemaRAG k=10；
- `c=16, q=16` 三次重复主实验；
- `c=1` 和 `c=32` 的端点缩放验证；
- makespan、有效吞吐、Token、P95/P99、CV、重试、队列和 RSS 遥测；
- 重复运行的离线统计、95% t 区间和论文图表。

当前第二部分的核心结论是：在 `kg-assist-pro`、冻结性能负载和单进程异步有界
Producer-Consumer 流水线条件下，M1 `budget-200` 相对 `full` 降低约 37% 总 Token，
并在固定 `c=16, q=16`、串行和高并发端点上表现出更短流水线时间和更高有效吞吐。

结论限定于当前模型、服务端状态和单进程实现，不延伸为队列最优性、多进程、多节点或
完整分布式系统结论。SchemaRAG 的在线 embedding 开销和端到端尾延迟已经纳入正式结果。
本部分的 `pipeline_ms`、makespan、Token 和吞吐是在线推理阶段指标，不包含 100 条
FullSchema 启动样本生成、训练数据构造、M1 离线训练或模型加载。若以后需要报告全
生命周期成本，应把一次性启动成本单独记录并按性能工作负载规模摊销，不能直接把当前
在线结果称为包含训练成本的总成本。
