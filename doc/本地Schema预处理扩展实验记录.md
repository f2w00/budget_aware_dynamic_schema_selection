# 本地 Schema 预处理扩展实验记录

## 目的

测量动态 Schema 的本地预处理能否按记录分片进行多进程扩展。实验只覆盖 M1 字段
Presence/长度预测、Budget-200 背包选择和 stable Prompt 构造；不调用 LLM API，不测量
远程服务吞吐、Token、请求延迟或端到端抽取质量。

## 协议

- 基础记录为 `data/hunan_museum_300000001_300000500_without_url/snapshot.jsonl` 的 500 条
  冻结记录。通过确定性循环复用构造 1,000、10,000、50,000 条工作负载；这只用于工程
  吞吐实验，不表示新增的数据分布或质量验证集。
- 模型为 `models/hunan_museum_300000001_300000500_without_url_n100_m1/seed_42`，使用线上
  `llm_runner.predict_fields()` 和 `llm_runner.schema_costs()`；选择器为
  `budget_selector.select_fields()`，预算为 200。
- 每个 worker 是独立 spawn 的 Python 进程，独立加载 M1 模型；记录按索引轮转分片。每个
  组合均包含 worker 启动和模型加载成本，重复 3 次，报告中位数。
- 峰值 RSS 为父进程及递归子进程树的总 RSS。每条记录的选择字段、估计成本和 Prompt 哈希
  被聚合为顺序无关摘要，以验证分片不改变输出。
- 测试机器为 16 个逻辑 CPU、约 22 GiB 内存的 Linux 环境。

## 结果

| 记录数 | Workers | 吞吐（records/s） | 相对 1 worker 加速比 | 并行效率 | 总耗时（s） | 峰值 RSS（MiB） |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 1 | 131.8 | 1.00x | 1.00 | 7.59 | 315.9 |
| 1,000 | 2 | 202.8 | 1.54x | 0.77 | 4.93 | 517.6 |
| 1,000 | 4 | 266.4 | 2.02x | 0.51 | 3.75 | 924.5 |
| 1,000 | 8 | 248.8 | 1.89x | 0.24 | 4.02 | 1,739.1 |
| 10,000 | 1 | 178.8 | 1.00x | 1.00 | 55.94 | 319.3 |
| 10,000 | 2 | 343.6 | 1.92x | 0.96 | 29.11 | 523.3 |
| 10,000 | 4 | 629.5 | 3.52x | 0.88 | 15.89 | 930.8 |
| 10,000 | 8 | 729.3 | 4.08x | 0.51 | 13.71 | 1,745.7 |
| 50,000 | 1 | 175.6 | 1.00x | 1.00 | 284.81 | 342.8 |
| 50,000 | 2 | 343.6 | 1.96x | 0.98 | 145.54 | 542.9 |
| 50,000 | 4 | 664.4 | 3.78x | 0.95 | 75.25 | 945.8 |
| 50,000 | 8 | 846.8 | 4.82x | 0.60 | 59.04 | 1,761.7 |

36/36 次正式运行的结果摘要均一致。大工作集下 2 和 4 worker 接近线性扩展；8 worker
仍能提升吞吐，但相对 4 worker 仅提高约 27.5%，同时峰值 RSS 约为 1.76 GiB，表明额外
进程的模型副本和调度开销已显著影响效率。

## 结论与边界

- 可以表述本地 Schema 预处理支持按记录分片的多进程并行，并在本机 50,000 条工作负载上
  从 1 到 4 worker 获得 `3.78x` 中位吞吐加速。
- 可以报告 8 worker 的 `4.82x` 加速，但必须同时报告并行效率降至 `0.60` 与约 `1.76 GiB`
  的峰值进程树 RSS，不能声称线性或无上限扩展。
- 该结果不代表端到端 LLM 抽取系统的可扩展性，因为它未包含远程服务限流、网络、队列、
  API 延迟、重试或服务端并发约束。
- 因此可在方法中使用“可并行的本地 Schema 预处理”或“多进程本地扩展实验”；不应仅凭此
  使用 `distributed`，也不应把远程 LLM 流水线称为线性 `scalable`。

## 产物与复现

- 基准脚本：`benchmarks/benchmark_local_schema_preprocessing.py`。
- 原始 36 次运行：`reports/local_schema_preprocessing_scaling.json`。

```bash
uv run python benchmarks/benchmark_local_schema_preprocessing.py \
  --output reports/local_schema_preprocessing_scaling.json
```
