# 第二部分 M1 初始化成本实验记录

## 1. 目的与边界

本实验补充第二部分在线流水线基准未覆盖的本地初始化成本，测量：

- 100 条训练样本下 M1 字段选择模型的离线训练时间；
- 线上已部署 M1 模型与隔离 100 条模型的冷加载时间；
- 100 条完整 Schema（`full`）任务的本地规划时间；
- 基于既有在线实验有效吞吐的 100 条 `full` 端到端时间换算。

本实验不创建 LLM 或 embedding 客户端，不调用任何模型接口。训练、加载与本地规划不属于已有的
在线推理指标，不能直接与在线流水线时间或 Token 成本相加。

## 2. 隔离与可复现性

执行脚本：`benchmarks/benchmark_initialization_cost.py`。

```bash
.venv/bin/python benchmarks/benchmark_initialization_cost.py
```

结果文件：`benchmarks/analysis/initialization/initialization_cost.json`。

为避免污染已用于主实验的模型：

- 脚本拒绝任何位于 `models/` 下的输出目录；
- 新训练模型仅写入 `benchmarks/analysis/initialization/artifacts/`；
- `models/field_selector` 只读加载，用于测量当前线上模型的加载和规划开销；
- 本地规划读取冻结性能负载 `data/performance/performance_ids_2000.json` 的前 100 条。

训练样本取自固定训练集的多标签贪心嵌套前缀，样本数为 100，使用 seed `42`、`43`、`44`。
每个 seed 产生一个独立 `model.joblib`，不会覆盖或替换任何已有模型产物。

## 3. 测量方法

### 3.1 M1 离线训练

对每个 seed 训练 char+word TF-IDF 特征、字段 Logistic Regression，以及字段长度 Ridge/中位数常数
模型。该过程只训练和序列化模型，不执行验证、测试或 LLM 推理。

### 3.2 冷加载

对 `models/field_selector` 重复 5 次调用当前 Runner 的 `load_models()`；同时对每个隔离 100 条模型重复
5 次。结果受操作系统文件缓存、磁盘和运行时版本影响，应作为本机部署开销描述。

### 3.3 100 条 full 本地规划

复用当前 Runner 的 `build_record_tasks()` 路径，测量完整 Schema 的 M1 `predict_fields()` 和 Prompt 构造。
不发起请求、不写入队列、不解析响应。因此该指标仅表示 Producer 本地规划开销，不代表端到端推理延迟。

### 3.4 在线时间换算

从已验证的 `full` 实验摘要读取有效吞吐，换算处理 100 条记录所需的端到端时间。该换算仅提供与本地
规划的量级对照，不与本地时间相加，也不构成新的在线运行。

## 4. 实测结果

| 项目 | 配置 | 结果 |
| --- | --- | ---: |
| 100 条 M1 隔离训练 | 3 seeds | 737.13 +/- 43.69 ms，最大 765.86 ms |
| 单个隔离模型文件 | 每个 seed | 3.36 MB |
| 已部署模型冷加载 | `models/field_selector`，5 次 | 178.26 +/- 14.43 ms，P95 197.44 ms，16.22 MB |
| 隔离 100 条模型冷加载 | 每个 seed 各 5 次 | 46.27--47.80 ms 均值，约 3.36 MB |
| 100 条 full 本地规划总计 | 已部署模型 | 366.63 ms |
| 100 条 full 本地规划 | 每条 | 3.09 +/- 0.16 ms，P95 3.25 ms |
| 其中 M1 字段预测 | 每条 | 3.04 +/- 0.16 ms |
| 其中 Prompt 构造 | 每条 | 0.05 +/- 0.02 ms |

三个隔离训练模型的训练时间分别为 686.86 ms、765.86 ms 和 758.68 ms；每个训练模型文件为
3,355,524 bytes。

## 5. 与在线流水线的关系

既有 `full` 在线结果换算如下：

| 在线配置 | 有效吞吐 | 100 条换算端到端时间 |
| --- | ---: | ---: |
| 主实验 `c=16, q=16` | 9.0573 records/s | 11.04 s |
| 串行端点 `c=1, q=1` | 0.6791 records/s | 147.26 s |

在主实验配置下，100 条本地规划 366.63 ms 约占换算端到端时间的 3.3%。该比例取决于服务端延迟和
并发设置；它不能推广为所有模型、硬件或服务状态下的固定比例。

训练与模型加载均为一次性成本，应按部署周期或累计处理记录数摊销：

```text
单条摊销成本 = 离线训练时间 / 累计服务记录数
             + 模型加载时间 / 单进程处理记录数
```

不得将一次性训练、加载时间逐条叠加到在线 Token、LLM 延迟或有效吞吐指标中。

## 6. 结论边界

- 实验确认当前 M1 的本地训练、加载和规划量级远小于串行在线 LLM 时间；
- 主实验的在线 `full` 路径包含 M1 预测，故该 3.04 ms/条预测时间已是在线 Producer 规划的一部分；
- 本实验未测量模型首次安装、环境创建、数据库冷缓存或多进程重复加载；
- 结果只适用于当前 Python、scikit-learn、硬件、文件缓存与模型版本。
