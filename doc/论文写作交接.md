## 3. 第一部分实验事实

### 3.1 数据与监督

- `training_dataset.jsonl`：6,763 条；
- Train/Validation/Test：5,410/677/676；
- `gold_main`：Test 中冻结的 500 条，不与 Train/Validation 重叠；
- 监督来源：既有 FullSchema 结果，属于 model-assisted silver reference，不是独立
  人工 Gold；
- `present` 标签表示 FullSchema 字段是否非空，不保证事实真实性；
- 长度标签是 FullSchema 字段值的 `cl100k_base` Token 数，不等于动态调用完整成本。

### 3.2 离线模型消融

n=100、五个 seed 的均值：

| 模型 | Presence Macro-F1 | Presence Micro-F1 | Length MAE |
| --- | ---: | ---: | ---: |
| 原始字符 TF-IDF | 0.5187 | 0.9126 | 4.8046 |
| M1：字符+词级 TF-IDF | 0.5088 | 0.9343 | 4.7615 |
| M2：概率融合 | 0.5083 | 0.9341 | 4.7615 |

准确解读：M1 的 Micro-F1 和 Length MAE 略优，但 Macro-F1 低于原始字符模型；收益
主要来自高频字段，未解决长尾字段。M2 没有额外收益，应作为负结果保留。

训练规模为 50/100/250/500/1000/2500/5410，每个规模五个 seed。训练量增加时，
Micro-F1 和 Length MAE 总体改善，但 Macro-F1 仍体现长尾限制。n=100 是低监督、
可部署的工程折中，不是离线通用最优规模。

### 3.3 离线预算回放

预算 100/200/400 的平均估计字段成本为 90.52/192.67/385.04，平均选中字段数为
2.75/4.81/8.23，FullSchema 非空字段覆盖率为 26.06%/53.46%/94.95%。

只能这样解释：预算选择器按预期控制字段范围，并且预算提高会提高离线覆盖率。不能
把覆盖率解释为事实正确率，也不能把估计字段成本解释为 API 实际成本。

### 3.4 真实 LLM 主方案

统一条件：

- API 服务名：`kg-assist-pro`；
- 底层模型：`Qwen3-8B-AWQ`；
- temperature：0；
- Qwen3 thinking：关闭；
- 并发：20；
- 队列：40；
- 最多 2 次重试；
- stable Prompt；
- M1 n=100，三个 seed，各 500 条完整成功。

M1 三种策略的 500 条三 seed 均值：

| 方法 | Macro-F1 | Micro-F1 | Exact Value Recall | 覆盖率 | 输入 Token | 输出 Token | 总 Token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| M1 + budget-200 | 0.7644 | 0.7673 | 0.6470 | 0.8381 | 321.1 | 64.4 | 385.5 |
| M1 + lambda=-0.003 | 0.7460 | 0.7544 | 0.6497 | 0.9878 | 342.0 | 120.1 | 462.2 |
| M1 + budget-400 | 0.7246 | 0.7329 | 0.6323 | 0.9906 | 360.7 | 132.4 | 493.2 |

当前主方案：

```text
M1 n=100 + stable Prompt + budget-200
```

准确解读：`budget-200` 是当前质量-Token 折中最好的候选。`lambda` 和 `budget-400`
提高字段覆盖，但没有带来更高端到端质量，说明覆盖率和质量不是单调关系。

### 3.5 八方法内部对照

统一旧一轮正式运行的 476 条共同成功样本：

| 方法 | Macro-F1 | Micro-F1 | Exact Recall | 覆盖率 | 总 Token |
| --- | ---: | ---: | ---: | ---: | ---: |
| full | .7623 | .7410 | .6528 | 1.0000 | 539.83 |
| prompt-null | .6215 | .5871 | .6557 | 1.0000 | 548.01 |
| prompt-omit | .7475 | .7386 | .6078 | 1.0000 | 487.10 |
| fixed-5 | .8400 | .8382 | .6056 | .7725 | 344.74 |
| fixed-10 | .6633 | .6619 | .6353 | .8409 | 409.39 |
| budget-200 | .7759 | .7780 | .6213 | .8303 | 381.49 |
| budget-400 | .7736 | .7638 | .6606 | .9763 | 486.32 |
| lambda-0.003 | .7822 | .7816 | .6407 | .9606 | 441.28 |

`fixed-5`/`fixed-10` 是固定高密度字段，受到字段先验偏置影响，只作补充诊断，
不能作为公平的动态方法主排序。

新 M1 三 seed 与历史 FullSchema 的 aligned476 对照来自不同调用批次，因此只能做
描述性比较：M1 `budget-200` 总 Token 385.9，历史 FullSchema 539.8，约低 28.5%；
M1 Micro-F1 数值更高，但 Exact Value Recall 略低。

### 3.6 SchemaRAG

SchemaRAG k=10/k=15 是基于论文描述的外部独立重实现，不是官方复现。

具体实现：

1. 字段名和字段定义分别调用 Embedding 服务；
2. 以 0.5/0.5 加权并进行 L2 归一化，形成字段向量；
3. 将固定检索指令与稳定序列化的 raw record 拼接为 query；
4. 调用 Embedding 服务得到 query 向量；
5. 与 18 个字段向量计算点积，归一化后等价于余弦相似度；
6. 按相似度降序选择 Top-10 或 Top-15 字段；
7. 用选中字段构造动态 Schema 并调用同一 LLM。

当前 Embedding 模型为 `Qwen3-Embedding-0.6B`。Schema 向量按 Schema、模型和权重
配置哈希缓存；每条记录的 query embedding 计入在线端到端时间，缓存读写/构建时间
单列记录。M1 长度预测只用于统一记录选中字段的估计字段成本，不参与 SchemaRAG
Top-k 选择，也不是 SchemaRAG 在线运行的必要模块。当前实现没有字段分段、示例检索
或二阶段重排序。

SchemaRAG 500 条结果：

| 方法 | Macro-F1 | Micro-F1 | Exact Recall | 覆盖率 | 总 Token |
| --- | ---: | ---: | ---: | ---: | ---: |
| k=10 | .7069 | .7022 | .4796 | .8078 | 432.9 |
| k=15 | .7324 | .7224 | .5524 | .9888 | 503.6 |

## 4. 第二部分实验事实

### 4.1 系统边界

当前系统准确称为：

```text
单进程异步有界 Producer--Consumer 预处理流水线
```

流程为：

```text
数据库记录
 -> Producer 读取与字段规划
 -> 有界 asyncio.Queue
 -> Consumer 并发调用 LLM
 -> 解析、校验、重试
 -> JSONL Writer
```

已有遥测包括规划时间、Embedding 时间、LLM 时间、解析校验时间、队列等待、入队阻塞、
Token、重试、P50/P95/P99、CV、队列峰值、Producer 阻塞、Consumer 空闲和 RSS。

当前不是多进程或多节点分布式系统，没有完成 shard/coordinator/distributed recovery。

### 4.2 主性能负载

- 记录数：2,000；
- 来源：训练集和验证集；
- 与第一部分测试集不重叠；
- 原始记录字节长度五个等频层，每层 400 条；
- 随机种子：`20260904`；
- 模型：`kg-assist-pro` / `Qwen3-8B-AWQ`；
- temperature：0；
- 最大重试：2；
- 方法：`full`、M1 `budget-200`、SchemaRAG k=10；
- 并发/队列：`c=16,q=16`；
- 每种方法 3 次重复。

主结果：

| 方法 | 成功率 | 平均流水线时间 | 有效吞吐 | 总 Token | P95 延迟 | P99 延迟 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| full | 100.0% | 220.82 s | 9.06 records/s | 1,709,102 | 2437.60 ms | 3601.20 ms |
| budget-200 | 100.0% | 113.64 s | 17.61 records/s | 1,069,254 | 1160.91 ms | 1307.50 ms |
| SchemaRAG k=10 | 99.9% | 399.68 s | 5.03 records/s | 1,230,411 | 4572.27 ms | 19885.52 ms |

相对 `full`，`budget-200`：

- 在线流水线时间降低 48.54%；
- 有效吞吐提高 94.38%；
- 总 Token 降低 37.44%。

SchemaRAG 的 Token 比 `full` 低 28.01%，但在线 query embedding 累计约 258.61 s，
导致整体时间增加 80.99%、有效吞吐降低 44.43%。这说明 Token 缩减不能脱离额外在线
阶段讨论，必须看端到端时间、成功率和尾延迟。

### 4.3 端点方向性验证

端点实验使用 500 条记录，比较：

```text
c=1,q=1
c=32,q=32
```

`full` 和 `budget-200` 在两个端点各重复两次，全部成功、无重试。关键结果：

| 方法 | 端点 | 流水线时间 | 有效吞吐 | P99 |
| --- | --- | ---: | ---: | ---: |
| full | c=1,q=1 | 733.49 s | 0.68 | 3035 ms |
| budget-200 | c=1,q=1 | 463.78 s | 1.15 | 1413 ms |
| full | c=32,q=32 | 91.04 s | 5.49 | 12024 ms |
| budget-200 | c=32,q=32 | 33.89 s | 14.76 | 2822 ms |

准确解读：两个观测端点都显示 `budget-200` 更快、吞吐更高；高并发端点同时出现
尾延迟放大。但由于并发和队列容量同时变化，该实验不是完整并发扫描，不能拆解纯
并发效应或纯队列容量效应。

### 4.4 初始化成本和在线计时边界

`pipeline_ms`、makespan、在线 Token 和吞吐只覆盖在线流水线：记录读取、任务规划、
入队、LLM 请求、重试、解析校验和结果写入。

不包含：

- 100 条 FullSchema 启动样本生成；
- 训练数据和银标标签构造；
- M1 离线训练；
- 模型或向量器加载。

当前 M1 使用既有 `training_dataset.jsonl`，训练阶段不调用 LLM。

已有本地测量：

- 100 条 M1 隔离训练三个 seed：`737.13 +/- 43.69 ms`；
- 训练后完整初始化保守合计：约 `0.915 s`；
- 已部署 M1 模型冷加载：`178.26 +/- 14.43 ms`，P95 `197.44 ms`；
- 100 条 `full` 本地 Producer 规划：`366.63 ms`，约 `3.09 ms/条`；
- 主实验 `full` 速率下 100 条在线时间约 `11.04 s`。

保守敏感性分析：若将完整 `0.915 s` 只加到 `budget-200` 一侧，`full` 为 220.82 s，
`budget-200` 为 114.56 s，性能领先方向不变。根据 100 条记录约 5.36 s 的在线时间差，
不对称假设下 break-even 约为 18 条；只计冷加载时约为 4 条。这两个数字是当前测量
条件下的敏感性估算，不是公平比较中 M1 必须单独回收的实际成本。

公平比较中 `full` 和 `budget-200` 共用同一个已训练 M1 模型，训练和加载属于共享或
部署成本，不能只作为动态方法的额外惩罚。SchemaRAG 的 query embedding 纳入在线
端到端时间，Schema 向量缓存时间单独记录。

## 10. 当前英文主稿结构

当前英文主稿为 `tex/paper/budget_aware_dynamic_schema_selection.tex`，题目为
`Budget-Aware Dynamic Schema Selection for Efficient LLM-Based Information
Extraction Pipelines`，正文结构如下：

```text
Introduction
Related Work
Method
  Pre-call Schema Pre-processing and Problem Formulation
  Data Representation and Silver Supervision
  Lightweight Field-Presence and Length Prediction
  Budgeted Record-Level Schema Pre-processing
Experiments
  Experimental Setup
    Compared Strategies and Controls
    Tested Embedding-Retrieval Adaptation
    End-to-End Pipeline Execution and Metrics
    Evaluation Reference and Metrics
    Workload and Experimental Conditions
  Experimental Results
    Main Field-Selection Comparison
    Selection-Strategy Ablation and Weight-Sensitivity Diagnostics
    End-to-End Pipeline Comparison
    Initialization Cost and Deployment Boundary
    Budget and Additional Baseline Analyses
    Concurrency and Queue Sensitivity
  Discussion
Conclusion
```

结构说明：

- `Method` 只介绍本文的问题定义、数据与银标监督、M1 预测器和动态字段选择方法。
- `Experiments` 负责实验协议、评价参考、基线实现、在线测量和实验结果。
- `Introduction` 将馆内编目约定、字段语义和重复文本模式作为适用条件，而非已验证的
  同质性或跨馆泛化结论。
- `Tested Embedding-Retrieval Adaptation` 位于 `Experimental Setup`，因为它描述的是
  SchemaRAG 外部基线在本文实验中的实现和运行协议，不是本文提出的方法。
- `Experimental Results` 先给出字段选择完整性和主在线比较，再给出初始化成本、预算响应及
  并发/队列容量敏感性等附加分析。
- `Initialization Cost and Deployment Boundary` 紧接主在线比较，用于解释选择器一次性成本和
  在线 break-even，不代表新的方法模块或完整生命周期成本结论。
- `Concurrency and Queue-Capacity Sensitivity` 是单进程条件下的方向性参数诊断，不能支持生产级
  并发扩展结论。
- `Discussion` 统一解释主结果、适用条件和证据边界，`Conclusion` 只保留带限定条件的核心结论。
