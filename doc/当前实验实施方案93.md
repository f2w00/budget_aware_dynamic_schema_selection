# 当前实验实施方案

## 1. 实验目标

当前实验回答两个相互关联的问题：

> 1. 在抽取质量相近的条件下，Adaptive Schema 是否比仅通过 Prompt 指导 LLM
>    忽略无信息字段消耗更少的 Token 和成本？
> 2. 在相同数据、模型和评估口径下，本文方法与已有外部方法相比处于什么水平？

本阶段不把并发、模型路由或全局预算调度作为实验变量。这样可以隔离
Schema 选择策略本身的质量和成本影响。外部方法只作为抽取策略对照，不引入其余
系统变量。

## 2. 实验范围

### 2.1 数据

- 使用冻结的 `data/gold/gold_main_ids.json` 对应记录。
- 所有方法使用完全相同的 `public.artifact_raw.raw_data`。
- 当前 Gold 主集建议使用已经生成的 500 条记录。
- 每种方法必须使用相同的 `artifact_id` 集合，并按 `artifact_id` 做配对分析。
- `artifact_extract` 只能用于历史弱监督分析，不作为本实验的独立真值。

### 2.2 固定条件

以下配置在正式运行前冻结：

- Schema 文件及 `schema_hash`。
- 基础 Prompt、Prompt-only Prompt 及各自的 `prompt_hash`。
- LLM 模型及模型版本。
- `temperature`、超时时间和最大重试次数。
- 单一 LLM Consumer；正式运行使用的并发值必须在运行前冻结并在所有方法中保持一致。
- 固定 `queue_size`，使用有界队列；队列大小不能成为方法比较变量。
- 字段权重、预算档位和 lambda 值。
- Token 价格和成本计算口径。

Producer-Queue-Consumer 结构仍然保留，但本阶段只使用：

```text
ML Producer -> 有界 Queue -> 单一 LLM Consumer -> Result Writer
```

队列用于统一任务接口、状态管理和后续扩展，不把队列并发能力作为本阶段
的结论依据。

## 3. 对照方法

建议正式运行以下内部方法：

| 方法 | 输入 Schema | Prompt 行为 | 作用 |
|---|---|---|---|
| `full` | 完整 18 字段 | 基础完整抽取指令 | Full Schema 参考 |
| `prompt-null` | 完整 18 字段 | 无信息字段输出 `null` | Prompt-only 主基线 |
| `prompt-omit` | 完整 18 字段 | 无信息字段允许省略 | Prompt-only 输出优化基线 |
| `fixed-5` | 固定 5 字段 | 基础抽取指令 | 固定 Schema 低成本基线 |
| `fixed-10` | 固定 10 字段 | 基础抽取指令 | 固定 Schema 中等成本基线 |
| `budget-200` | 预算 200 内自适应字段 | 基础抽取指令 | 低预算 Adaptive |
| `budget-400` | 预算 400 内自适应字段 | 基础抽取指令 | 中等预算 Adaptive |
| `lambda-0.003` | 净效用选择字段 | 基础抽取指令 | 无硬预算 Adaptive |

核心结论比较为：

```text
prompt-null / prompt-omit vs budget-200 / budget-400 / lambda-0.003
```

其中 `prompt-null` 是最严格、最容易解释的 Prompt-only 基线；
`prompt-omit` 用于检验即使允许模型省略输出字段，Prompt-only 是否仍然
因为输入完整 Schema 而产生较高成本。

### 3.1 外部方法对照

上表中的 `fixed-*`、`budget-*` 和 `lambda-*` 都是本文方法的内部变体，不能称为
“别人提出的方法”。正式论文比较还需要加入至少一种与动态 Schema 选择、字段裁剪或
预算约束信息抽取直接相关的外部方法。

外部方法必须先完成以下步骤，再进入正式运行：

1. 确定具体论文、版本、算法名称和可核验引用。
2. 明确该方法的输入、字段选择规则、预算约束和输出协议。
3. 优先按论文实现；若论文代码公开，记录代码版本和配置；若无法完整复现，必须标记
   为“基于论文描述的重实现”，不能表述为原作者官方实现。
4. 将外部方法适配到当前 18 字段 Schema 时，只改变字段选择策略，不改变 raw 输入、
   LLM、Prompt、temperature、重试、解析和评估规则。
5. 在同一批 500 条 Gold 记录上运行，并按 `artifact_id` 与所有内部方法配对。

外部方法在确定具体论文前使用占位名，不提前填入不存在的结果：

| 类别 | 方法 | 当前状态 | 作用 |
|---|---|---|---|
| 外部方法 | `external-method-A` | 待选定并复现 | 与本文 Adaptive Schema 的直接对照 |
| 外部方法 | `external-method-B` | 可选，待评估相关性 | 外部方法稳健性对照 |

外部方法的主比较表必须与内部方法使用同一套字段选择、LLM 调用和离线评估结果，
不能直接引用外部论文在其他数据集、模型或指标下的数字作为本实验结果。

## 4. 预算和成本口径

每个任务同时保存以下四个值：

```text
C_full       = 所有 18 个字段的估计字段成本之和
B_required  = 当前方法选中字段的估计成本之和
B_allocated  = Scheduler 实际分配的预算
C_actual    = LLM 实际 input + output Token，包含重试资源
```

字段估计成本为：

```text
field_name_tokens
+ schema_value_tokens
+ predicted_output_tokens
```

`C_full` 只作为 Full Schema 成本基准，不能当作 Adaptive 的任务预算。
Adaptive 的 `B_required` 只对选中的字段求和。

原始记录输入 Token 不参与字段组合预算，但必须记录在真实 LLM 结果中。

## 5. 运行阶段

### 5.1 任务计划检查

正式调用前先生成少量任务计划：

```bash
uv run python task_planner.py \
  --split test \
  --limit 30 \
  --methods full prompt-null prompt-omit fixed-5 fixed-10 \
    budget-200 budget-400 lambda-0.003 \
  --output experiments/task_plan_current_smoke.jsonl
```

检查：

- 每个 `artifact_id` 都有全部指定方法。
- `full`、`prompt-null` 和 `prompt-omit` 均选择 18 个字段。
- Adaptive 方法的 `selected_fields` 与预算选择器输出一致。
- `B_required` 不超过对应方法的预算上限（无硬预算方法除外）。
- `C_full` 对同一条记录在不同方法中相同。
- 同一条记录的多个方法复用一次 ML 字段预测。

### 5.2 单并发 LLM 冒烟

先用少量记录确认调用、解析、重试和断点续跑：

```bash
uv run python llm_runner.py \
  --split test \
  --limit 10 \
  --methods full prompt-null prompt-omit fixed-5 fixed-10 \
    budget-200 budget-400 lambda-0.003 \
  --max-concurrency 1 \
  --queue-size 2 \
  --output experiments/current_single_consumer_smoke.jsonl \
  --experiment-id current-single-consumer-smoke-v1
```

冒烟阶段只检查管线，不作质量结论。必须确认：

- 任务全部进入队列并完成或被明确记录为失败。
- `prompt-null` 和 `prompt-omit` 的 Prompt 版本可区分。
- Adaptive 任务的字段集合正确。
- 结果只包含目标字段，缺失字段处理符合方法定义。
- `input_tokens`、`output_tokens`、`total_tokens`、`retry_count` 和延迟字段存在。
- 已成功任务可以断点续跑而不重复调用。

### 5.3 正式单模型实验

冒烟通过后，使用完整 Gold 主集运行上述 8 种内部方法及已确认的外部方法。建议每种方法单独保存
结果文件，便于失败重跑和分析：

```text
experiments/full_gold_main.jsonl
experiments/prompt_null_gold_main.jsonl
experiments/prompt_omit_gold_main.jsonl
experiments/fixed5_gold_main.jsonl
experiments/fixed10_gold_main.jsonl
experiments/budget200_gold_main.jsonl
experiments/budget400_gold_main.jsonl
experiments/lambda003_gold_main.jsonl
experiments/external_method_a_gold_main.jsonl
```

所有方法必须使用相同的 Gold ID 清单、模型、单消费者配置和有限重试策略。
已经完成的 v3 Pro 结果可以直接用于 `full`、`prompt-null` 和 `prompt-omit` 的离线评估；
只有尚未运行的方法才需要补充 LLM 调用。

## 6. 记录指标

### 6.1 质量指标

使用补全后的 `gold_main.jsonl`，至少报告：

- Presence-F1 Macro 和 Micro。
- Reference-present Recall。
- Reference-absent False Positive Rate。
- 非 `desc` 字段的 LLM Value Score。
- `desc` 字段的固定模型 Embedding Score。
- 综合 Quality 分数及三个分项。

综合质量分数固定为：

```text
Quality = 0.5 * Presence-F1
        + 0.3 * LLM-Value-Score
        + 0.2 * Desc-Embedding-Score
```

不能只报告总分，也不能把与 `artifact_extract` 的一致率称为真实准确率。

### 6.2 成本指标

- `C_full`、`B_required`、`B_allocated`、`C_actual`。
- 平均、P50、P95 `input_tokens`。
- 平均、P50、P95 `output_tokens`。
- 平均、P50、P95 `total_tokens`。
- 实际 API 成本。
- 重试次数和失败率。

相对于 Prompt-only 基线的 Token 节省率为：

```text
Token Reduction = 1 - Adaptive C_actual / Prompt-only C_actual
```

必须分别报告输入、输出和总 Token 节省率。

### 6.3 单消费者系统指标

本阶段只作为运行诊断记录，不作为并发扩展性结论：

- `producer_time_ms`。
- `queue_wait_ms`。
- LLM 服务时间。
- 结果解析时间。
- 端到端延迟。
- 任务成功率、失败率和重试率。

## 7. 主要分析

### 7.1 成本-质量比较

对每个 `artifact_id` 做配对比较，分别完成内部比较和外部比较：

```text
Adaptive C_actual vs Prompt-only C_actual
Adaptive Quality vs Prompt-only Quality
本文方法 Quality vs External-method Quality
本文方法 C_actual vs External-method C_actual
```

主要结论应满足：

```text
Adaptive Quality 与 Prompt-only 接近
且 Adaptive 的实际总 Token 更低
```

绘制：

- 方法平均质量与平均总 Token 对比图。
- 每条记录的 Adaptive 相对 Prompt-only Token 差异图。
- Cost-Quality 曲线。
- 不同预算下的质量和成本曲线。
- 外部方法与本文方法的质量-成本散点图及配对差值图。

### 7.2 最终比较表

最终表格按以下层次组织，避免把内部变体误写成外部基线：

| 层次 | 包含方法 | 解释 |
|---|---|---|
| 完整 Schema 基线 | `full` | 输入全部字段的基础方法 |
| Prompt-only 基线 | `prompt-null`、`prompt-omit` | 只改变 Prompt 行为 |
| 本文方法内部对照 | `fixed-*`、`budget-*`、`lambda-*` | 验证字段选择和预算设计 |
| 外部方法 | 已确认的 `external-method-*` | 与文献方法进行公平复现比较 |

每行同时输出最终成功率、失败率、累计 Token、Presence、Value、`desc` 相似度和综合
Quality。最终失败任务不参与输出质量分数，但其重试和已消耗 Token 必须计入效率指标。

### 7.3 结论边界

本阶段可以支持的结论：

```text
在固定模型、固定单消费者和相同记录条件下，
Adaptive Schema 是否能以相近质量降低 LLM Token 消耗。
```

本阶段不能支持的结论：

```text
Adaptive 提升了大规模吞吐量。
多模型路由降低了成本。
并发和背压优于其他调度策略。
本文方法普遍优于所有已有方法。
```

只有在至少一种外部方法完成同条件复现，并且完成质量与成本的配对分析后，才能讨论
“本文方法相较该外部方法”的结论；不能根据当前内部 Prompt 对照或旧实验结果外推。

## 8. 后续实验

完成本阶段并确认 Schema 选择收益后，再单独开展：

1. 并发扩展实验：固定抽取策略，比较 `concurrency=1/5/10` 的吞吐、延迟、
   队列等待和稳定性。
2. 多 Worker 实验：固定 Schema 策略，比较快速模型与高质量模型的路由效果。
3. 全局预算实验：让 Scheduler 在任务之间分配有限总预算，研究降级、升级和
   背压策略。

这些实验应分别改变一个主要变量，不能与当前质量-成本主实验混合。
