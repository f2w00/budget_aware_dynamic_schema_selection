# 论文中文主稿 v4 审稿意见

## 审稿设置

- **审阅对象**：`论文中文主稿v4.tex`
- **审阅范围**：全文，共 811 行
- **评审方式**：三名互盲审稿人独立审阅，并在报告冻结后进行交叉综合
- **总体建议**：大修后重审（Major Revision）
- **评估边界**：审稿仅基于主稿中的文字、公式、表格、图注和方法描述。未获得原始记录、人工 Gold、逐次运行日志、完整代码仓库、图像渲染结果或外部数据集。

## 总体判断

稿件研究一个具有现实意义的系统问题，即是否可以针对每条异构文化遗产记录选择较小的目标 Schema，从而减少 LLM 结构化抽取的 Token 和在线运行负载。作者将字段存在性预测、输出长度估计、任务价值权重和 0-1 背包选择连接到异步 Producer-Consumer 流水线，并分别报告离线选择结果、冻结测试集上的 LLM 抽取结果和独立性能负载结果。

稿件最可信的结论是，在当前数据、18 字段 Schema、特定 LLM 服务和单进程异步流水线条件下，记录级动态 Schema 裁剪能够复现部分 FullSchema 输出行为，并同时降低实测 Token 和在线运行时间。当前证据尚不足以证明真实事实抽取质量保持、动态 Schema 相对于相关方法具有普适优越性，或标题所称的生产级可扩展性。

论文的主要优点是问题定义和成本口径较清楚，并主动区分银标一致性、实际 Token、在线时间和完整生命周期成本。然而，质量监督与评价均来自同源 FullSchema 模型辅助银标，主比较存在跨批次和有限外部适配问题，长尾字段证据不足，在线实验缺少运行级不确定性，复现材料也不完整。

# Reviewer 1

## Overall assessment

稿件对文化遗产记录中的记录级 Schema 选择问题进行了较完整的系统化讨论。问题具有现实工程动机，实验也覆盖字段选择、LLM 抽取和流水线性能三个层次。作者对银标、SchemaRAG 外部适配、单进程流水线和初始化成本边界的披露较为坦诚。

但当前结果主要证明了两点。第一，动态方法能够在一定程度上模仿 FullSchema 的模型辅助输出行为。第二，在一个固定数据集、模型服务和单进程配置下，裁剪 Schema 能够减少请求负载。现有证据不能充分支撑真实事实质量保持、方法学普适优越性和可扩展框架等更强主张。

## Who would be interested in the results, and why

文化遗产数据库和数字人文研究者会关注该工作，因为它处理了记录异构、字段稀疏和批量结构化处理问题。LLM 信息抽取、成本敏感推理、Prompt 优化和推理服务研究者也可能关注，因为稿件直接考察 Schema 大小、字段覆盖、输出行为和请求负载之间的关系。数据工程和批处理系统实践者可能受益于有界队列、重试、结果写入和断点续跑设计。

目前对更广泛机器学习和自然科学读者的吸引力有限。实验仅覆盖一个数据集、18 个预定义字段、一个 LLM 服务和一个单进程实现，且主要质量参照来自同一 FullSchema 模型过程。

## Major strengths

- 研究问题具有明确的工程动机，同时考察字段指标、Coverage、运行时间、有效吞吐和尾延迟。
- 稿件区分了估计字段成本、实测 Token 和货币成本，见第 97 至 111 行和第 359 至 370 行。
- 作者明确披露 `artifact_extract` 是模型辅助银标而非人工真值，见第 208 至 216 行。
- 文章分别组织离线选择、LLM 抽取和系统性能实验，避免直接用离线覆盖率替代在线结果。
- 在线主实验覆盖读取、任务构造、入队、请求、重试和写入，较接近实际流水线。
- 作者没有将 `budget-200` 宣称为全局最优预算，而是将其定位为当前条件下的工程折中。

## Major Concerns

### R1-M1 质量评价缺少独立事实真值

- **Severity**：Major
- **Blocking**：Yes
- **Axis**：中央主张有效性、技术可靠性、主张克制
- **Claim pointer**：摘要第 48 至 56 行和结论第 762 至 767 行声称动态 Schema 可以在不显著损害字段级抽取质量的情况下减少负载。
- **Evidence pointer**：第 208 至 216 行、第 232 至 239 行、第 532 至 537 行及第 745 至 754 行。
- **Concern**：质量评价主要以 FullSchema 产生的模型辅助银标签为参照。训练标签、字段存在性评价和 Exact Value Recall 都可能衡量动态策略对 FullSchema 输出行为的重现，而不是事实是否正确。
- **Why it matters**：如果 FullSchema 存在遗漏、幻觉或错误归因，动态方法可能只是更好地复制教师模型的错误。当前证据不能区分保持真实抽取能力和保持模型输出习惯。
- **Resolution test**：在与训练和策略选择隔离的记录上建立人工或原始证据核验 Gold，分别报告字段存在性、字段值正确性、遗漏、错误新增和无法判定案例。若无法获得独立 Gold，应将质量主张统一改写为“对 FullSchema 银标签的行为一致性”。

- **Evidence pointer**：第 97 至 108 行、第 261 至 286 行、第 785 至 799 行。

- **Why it matters**：将成熟组件组合到应用流水线可能具有系统价值，但目前尚未证明其相对于最接近工作的独特方法学增量。

### R1-M3 缺少逐字段和长尾字段证据

- **Blocking**：Yes
- **Axis**：长尾有效性、科学重要性、中央主张连贯性
- **Claim pointer**：引言、摘要和结论强调质量、覆盖和负载之间的折中，并将长尾字段遗漏列为关键风险。

- **Blocking**：Yes
- **Axis**：比较有效性、主张连贯性、统计证据
- **Claim pointer**：摘要第 53 至 56 行将方法描述为相对于 SchemaRAG 具有更高字段一致性和更低 Token。

- **Why it matters**：服务状态、模型版本、Prompt、解码参数和批次时序都可能影响质量、Token 和时间，当前结果不能可靠归因于字段选择机制。

### R1-M5 “可扩展”定位超出实验范围

- **Severity**：Major
- **Blocking**：Yes
- **Axis**：可扩展性、广泛兴趣、外部有效性
- **Claim pointer**：标题使用“可扩展 LLM 预处理框架”，摘要和结论也有相应工程外推。

### R1-M6 在线性能缺少运行级不确定性

- **Severity**：Major
- **Blocking**：Yes
- **Axis**：系统性能证据、统计可靠性

## Nature-style criteria

- **Originality**：记录级、预算约束的 Schema 选择具有应用价值，但算法主体由成熟组件组成，尚未充分证明相对于最接近工作的独特增量。
- **Scientific importance**：减少 LLM 结构化抽取负载是重要问题，但当前证据限于单一数据集和服务配置，事实质量没有独立验证。
- **Interdisciplinary readership**：当前主要吸引数字人文、信息抽取和 LLM 系统工程读者。独立事实质量、长尾保真和跨配置验证将决定能否扩大读者范围。
- **Technical soundness**：方法描述总体清楚，但独立 Gold、严格配对比较、长尾分析和性能不确定性是实质性缺口。
- **Readability for nonspecialists**：结构清晰，边界披露较好，但相关工作位置偏后，指标和中央贡献仍需进一步简化。
- **Claim moderation**：标题中的“可扩展”、摘要中的“不显著损害质量”和相对于 SchemaRAG 的优越性表述仍强于当前证据。

## Recommendation posture

建议大修后重新评估。当前稿件提供了有价值且披露较透明的工程原型，但尚不足以支撑高选择性综合期刊所要求的原创性、事实有效性和广泛重要性。

# Reviewer 2

## Overall assessment

本文提出一种面向文化遗产记录的记录级动态 Schema 选择流程。方法使用 FullSchema 抽取产生的模型辅助银标签训练字段存在性和输出长度预测器，再通过字段效用、估计成本及 0-1 背包构造预算约束的动态 Schema。作者进一步报告冻结记录上的抽取指标，以及 2,000 条记录上的在线流水线时间、吞吐量和 Token 负载。

稿件的工程问题意识较清楚，明确区分了字段选择质量、LLM 抽取质量和流水线性能，也主动限定了银标签、SchemaRAG 外部适配、单进程流水线和初始化成本等边界。但是，当前证据主要证明方法能够复现 FullSchema 的模型辅助行为，并在特定数据集、模型服务和并发设置下减少请求负载。

## Who would be interested in the results, and why

文化遗产数字化、结构化信息抽取、LLM 预处理和 LLM serving 系统研究者可能对该工作感兴趣，因为它将 Schema 选择从静态配置转化为记录级调用前决策，并尝试把字段裁剪收益传递到在线系统指标。对缺少大规模人工字段标注的应用团队，该流程也可能提供一种低成本工程基线。

不过，对更广泛的机器学习、信息抽取和系统研究读者而言，当前证据仍主要是数据集和部署条件内的案例结果。是否能推广到不同字段集合、人工标注体系、模型服务、数据分布和负载规模，尚未得到验证。

## Major strengths

- 将离线字段选择、冻结记录上的抽取结果和独立性能负载分开评估。
- 清楚描述预测器、效用和成本估计、预算选择、动态 Schema、LLM 调用和结果写入。
- 明确说明 `artifact_extract` 是模型辅助银标签，而非人工真值。
- 对训练集、验证集隔离、TF-IDF 拟合、长度回归和缺少正样本时的回退规则有所说明。
- 区分 `fixed-5`、`fixed-10` 等诊断性基线与动态方法主基线。
- 在线实验报告成功率、makespan、有效吞吐、总 Token 和 P99。
- 对单进程异步流水线、并发、队列容量、初始化成本和 SchemaRAG 适用范围做了明确限定。

## Major Concerns

### R2-M1 质量参照缺少独立性

- **Severity**：Major
- **Blocking**：Yes
- **Axis**：技术可靠性、科学重要性
- **Claim pointer**：方法能够通过少量 FullSchema 银标签支持动态 Schema 选择，并在冻结测试集上代表实际抽取质量。
- **Evidence pointer**：摘要第 48 至 62 行、第 208 至 216 行、第 534 至 537 行及结论第 762 至 767 行。
- **Concern**：字段质量评价以 FullSchema 模型辅助银标签为参照，主要衡量动态策略对 FullSchema 输出行为的重现，而不是字段事实是否正确。
- **Why it matters**：当前实验不能回答动态 Schema 是否保留了真实文化遗产事实，也不能确定字段裁剪是否牺牲了 FullSchema 未正确生成的长尾信息。
- **Resolution test**：引入独立人工标注、专家核验或可追溯原始证据验证集，分别报告 Presence、Exact Value、字段级 Macro-F1 和长尾字段表现。若无法提供，应将质量表述改为相对于 FullSchema 银标签的行为一致性。

### R2-M2 100 条监督样本的采样依据不足

- **Blocking**：Yes

## Other consensus major concerns

- **基线比较不够严格**：`R1-M4`、`R2-M4` 和 `R3-M4` 均指出 SchemaRAG 是有限外部适配，FullSchema 与新 M1 还存在跨批次差异。因此目前只能支持相对于本文特定外部适配实现的描述性结果。
- **可扩展性证据不足**：`R1-M5`、`R2-M7` 和 `R3-M5` 均指出，2,000 条记录、单进程、单服务和固定并发配置不足以支持“可扩展”这一标题级主张。
- **权重、预算和成本代理量需要更清楚**：`R1-M7` 和 `R2-M5` 指出字段权重、`budget-200`、`budget-400` 和 `lambda=0.003` 的来源及敏感性不足。
- **逐字段和长尾字段结果不足**：`R1-M3` 重点指出，聚合指标可能被高频字段主导，当前尚不能判断动态裁剪是否牺牲低频但高价值字段。

## Where emphasis differs across reviewers

- Reviewer 1 更强调原创性定位、长尾字段风险、字段权重和标题中的“可扩展”表述。
- Reviewer 2 更强调 100 条启动样本的采样协议、预算目标定义和完整复现材料。
- Reviewer 3 更强调共同成功记录带来的选择偏差、完整测试集失败分析以及在线图表和结果集合之间的内部一致性。

## Minor revision checklist

- 明确 Presence F1、Exact Value Recall、Coverage 和 Recovery 的公式、分母、空值处理和字符串规范化规则。
- 报告数据来源、时间范围、语言组成、去重规则、许可限制和数据治理信息。
- 将“不显著损害”改为描述性表述，除非补充非劣效界值和统计分析。
- 提供逐 seed 的指标，而不仅是三种或五种 seed 的均值。
- 明确五个 seed 的置信区间计算方式。
- 报告每种方法在完整 500 条记录上的初始失败、重试成功、最终失败和错误类型。
- 将共同成功子集分析改为敏感性分析，并增加以全部记录为分母的结果。
- 统一说明不同表格中 `budget-200` 结果的记录集合、调用批次、seed 和聚合方式。
- 说明模型版本、量化实现、硬件、服务软件、解码参数、embedding 模型和缓存状态。
- 集中说明在线计时的起止点、排除项和未测量成本。
- 将最接近的相关工作定位提前到引言或方法部分。
- 在图注和正文中说明哪些指标衡量银标一致性，哪些指标衡量系统负载，哪些指标不能代表真实事实正确性或货币成本。

## Broad-interest and significance readout

稿件对文化遗产信息系统、结构化信息抽取和 LLM 服务工程具有明确的潜在价值。当前结果更适合被解释为一种受限条件下的工程验证，而不是已经建立的通用动态 Schema 方法。

若能补充独立事实质量、长尾字段保真、严格匹配的外部基线、跨分布负载和运行级不确定性，稿件的科学重要性和跨学科吸引力会明显提高。若不能补充这些证据，应收窄标题、摘要和结论，将贡献定位为单一文化遗产数据集和特定模型服务条件下的成本感知 Schema 裁剪流程。

## Most important issues to resolve

1. 建立独立事实质量评价，或全面将质量主张改为 FullSchema 银标行为一致性。
2. 对完整测试集报告所有策略的成功、失败、重试和解析结果。
3. 报告逐次性能运行值、离散度、不确定性和运行控制信息。
4. 重新组织 FullSchema、SchemaRAG 和其他基线的公平比较。
5. 增加逐字段和长尾字段结果。
6. 说明 100 条启动样本、字段权重、预算和 lambda 的来源及敏感性。
7. 提供完整代码、配置、Prompt、环境和可复现实验资产，或明确无法复核的结果范围。
8. 删除或收窄缺少规模、并发和多部署证据支持的“可扩展”表述。

## Risk / unsupported claims

- “不显著损害字段级抽取质量”没有独立事实 Gold 或非劣效检验支持。
- 当前质量指标主要衡量与 FullSchema 银标签的一致性，不能直接解释为事实准确率。
- “少量监督”受到 100 条启动样本采样协议和嵌套前缀设计影响。
- `budget-200` 的预算不是 API Token 上限、货币成本上限或全生命周期成本上限。
- `budget-200` 的工程折中效果可能依赖字段权重和 `lambda=0.003`。
- 相对于 SchemaRAG 的优势只能解释为相对于本文特定固定 Top-k 外部适配的结果。
- FullSchema 与新 M1 的跨批次差异削弱了严格优越性比较。
- 476 条共同成功记录可能掩盖策略相关失败，不能代表完整测试集上的无条件质量。
- 2,000 条训练集和验证集构成的性能负载并非对选择器训练分布完全独立。
- 单进程、单模型服务、固定并发和有限负载不足以支持生产规模或多节点可扩展性。
- 在线性能改善百分比缺少运行级不确定性，当前稳定性不可评估。
- 当前稿件未完整提供代码、配置、Prompt、运行日志、原始数据或派生结果，独立复现能力有限。
- 初始化样本生成、模型加载、环境安装、数据库冷缓存和多进程加载成本未纳入主要在线结果，不能据此宣称完整生命周期成本下降。

## 结论

三位独立审稿人的共同判断是，稿件具有明确的工程问题和一定系统价值，但当前最重要的质量证据存在 FullSchema 银标闭环，性能证据缺少运行级不确定性，方法比较和“可扩展”定位也超出了现有实验范围。建议大修后重新评估。
